## Category legend

- **Role taxonomy** (A-K): every built-in role type plus custom roles, unknown-type discipline.
- **Tiering** (L-T): privilege-tier mapping for every built-in role type, with documented justification per tier.
- **User assignments** (U-AB): Super Admin / high / medium / read-only addition and removal severities, dedup, identity stability.
- **Group assignments** (AC-AH): group-carried admin roles, scope, dedup, ordinary-group non-effect.
- **Effective privilege** (AI-AQ): direct vs. group-inherited privilege distinction, highest-tier selection, dedup, unknown-role visibility, boolean rollups.
- **Lifecycle combinations** (AR-AZ): Active/Suspended/Deprovisioned Super Admin, reactivation severities, dormant-privileged posture.
- **Group membership privilege** (BA-BF): joining/leaving privileged groups, tier-dependent severity, suspended-member visibility, dedup.
- **Custom roles** (BG-BM): permission-category-to-tier mapping, unknown-permission discipline, resource-set scope categorization.
- **Collection** (BN-BV): per-family independent failure modes, pagination (object-wrapped IAM endpoints and classic Link-header), cross-origin rejection, bounded N+1 walk.
- **Unknown safety** (BW-CA): the four explicit unknown-state disciplines from the task spec, each independently verified.
- **Diff/classification** (CB-CN): real `compute_diff()` -> `classify_okta_change()` for every required severity case in the task's structural-risk-classification section.
- **Metadata** (CO-CS): provider metadata correctness and secret-exclusion for every new record type.
- **Scale** (CT-CW): bounded per-user role-enumeration walk under load, custom-role collection at scale.
- **Security boundary** (CX-DB): sensitive-data exclusion for API tokens, raw permission payloads, profile extras, resource-set URLs, and factor secrets.
